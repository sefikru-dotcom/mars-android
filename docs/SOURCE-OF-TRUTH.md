# Где истина mars-android — читать ДО любой правки

Дата: 24.11.2026. Причина появления: серверный инстанс Марса дорабатывал музыку на устаревшей
копии (`main` @ `8060affc`, октябрь), потому что 32 коммита ноутбука за ноябрь не были
запушены. Результат — доработка поверх старой базы и потерянные волны 13–22. Чтобы это не
повторилось, правило одно, и оно не зависит от того, какая машина «главнее».

## Правило

**Источник истины — ветки в GitHub (`sefikru-dotcom/mars-android`), а не рабочий каталог
какой-либо машины.** Ноутбук, сервер, любой другой инстанс — только клоны.

Следствия для любого агента (ноутбук, сервер, воркер):

1. **Перед правкой — `git fetch --all` и смотреть, что новее в origin.** Если локальное дерево
   уходит вперёд, а в origin нет — правка по origin будет сделана по устаревшей базе.
2. **Локальные коммиты, которых нет в origin, считаются несуществующими для остальных.**
   Закончил волну — запушь ветку в тот же ход. Незапушенная работа — это работа, которую
   следующий агент обязательно продублирует или затрёт.
3. **Не мержить слепо.** Перед слиянием чужой линии проверить:
   `git merge-base <своя> <чужая>` и `git log --oneline <merge-base>..<чужая> | wc -l` —
   если у «базы» сотни отсутствующих коммитов, это не база, а старая копия.
4. **`main` = прод.** Push в `main` с зелёным CI автоматически публикует релиз на
   marscore.ru (`docs/RELEASE.md`). В `main` уходит только то, что принято владельцем на
   телефоне. Всё остальное живёт в ветках.
5. **Номер версии (`versionCode`/`versionName`) поднимает только релиз-коммит** после
   приёмки. Рабочие ветки версию не трогают — иначе две ветки «спорят», кто новее.

## Актуальные ветки

| Ветка | Что | Статус |
|---|---|---|
| `main` | прод, публикуется CI | только принятое владельцем |
| `feat/local-chat-wave` | ноябрьская линия ноутбука (волны 1–22: локальный чат, голос, 3D-орб, стекло, виджеты) | слита в `feat/music-on-laptop` |
| `feat/music-on-laptop` | **актуальная линия**: ноутбук + музыка сервера + доработка музыки | здесь ведётся работа |

Устаревшее, не использовать как базу:

| Ветка | Почему |
|---|---|
| `run/music-wave`, `integrate/music-wave`, `wave/m1-notif`, `wave/m2-widget`, `wave/m3-player` | музыкальная волна сервера поверх октября; влита в `feat/music-on-laptop` |
| `run/laptop-plus-music` | попытка сервера склеить музыку с ноутбуком по базе 01.11 — **без волн 13–22**; версию 1.9.2 (47) из неё не переносить |

## Как собрать на ноутбуке (PCLite)

`./gradlew` на MSYS падает (`ClassNotFoundException: GradleWrapperMain`). Рабочий способ —
`C:\Users\SKY\.zcode\workspace\default\build-mars.sh <task>` (запускает wrapper напрямую).
Свежему worktree нужны два файла вне git: `local.properties` и `app-mobile/google-services.json`
(скопировать из основного дерева).

## Чего больше не делать

- «Источник истины — ноутбук» (так писали `docs/LOCAL-CHAT-WAVE-STATE.md` 01.11) — больше не
  действует: ноутбук может отстать от GitHub ровно так же, как сервер.
- Хранить работу только в рабочем каталоге, в бандлах (`*.tgz`, `*.bundle`) или в `/root/workspace`
  на сервере.
- Держать в репо архивы исходников (`mars-local-full.tgz`, 16 МБ) — это и есть «вторая копия
  кода», из которой потом берут неактуальную версию.
