# Волна 9: голос, модели, картинки

Четыре задачи владельца. Каждая — отдельный воркер, зоны не пересекаются.

## §1. Голос: убрать роботность (ГЛАВНОЕ)

Сейчас Piper `ru_RU-irina-medium-int8` РАБОТАЕТ (подтверждено на устройстве:
`AudioTrack: set() sampleRate 22050` — это частота Piper, не системного TTS).
Но голос звучит роботом. Три причины, чинить все:

**а) int8-квантование.** `ru_RU-irina-medium.onnx` — 18.5 МБ, int8. У Piper есть
полноточная версия той же модели: `vits-piper-ru_RU-irina-medium` (без `-int8`),
~63 МБ, заметно чище. Разница слышна сразу.

**б) `AudioTrack underrun`.** В логе:
```
W AudioTrack: restartIfDisabled(12676): releaseBuffer() track ... disabled due to previous underrun
```
Значит куски PCM подаются реже, чем проигрываются, — звук рвётся и «дребезжит».
Причина: `generateWithCallback` отдаёт float-куски, а мы проигрываем их сразу,
без буфера упреждения. Нужен буфер на 2–3 куска вперёд.

**в) Параметры инференса.** В `ru_RU-irina-medium.onnx.json` есть `noise_scale`,
`noise_scale_w`, `length_scale`. Заводские значения дают «плоское» чтение.
Для живого голоса: `noise_scale` 0.667 (заводской) → попробовать 0.5–0.7;
`length_scale` 1.0 → 1.05–1.15 (медленнее = естественнее).

**Что сделать:**
1. Перевести манифест на полную модель (без int8), пересчитать размеры и SHA-256
   по реально скачанному архиву. Старый int8-файл оставить как запасной вариант,
   если полная не скачалась (не ломать офлайн-сценарий).
2. В `OfflineTtsBackend` — буфер упреждения: не подавать кусок в `AudioTrack`,
   пока предыдущий не проигран хотя бы наполовину. Цель — ноль `underrun` в логе.
3. Вынести `noiseScale` / `lengthScale` в параметры с дефолтами, дать
   возможность менять без пересборки (константы в манифесте достаточно).

**Проверка:** собрать WAV из нескольких фраз и приложить их пути. Замерить:
длительность, отсутствие провалов (нет участков нулевой амплитуды длиннее 20 мс
внутри слова), спектр не обрезан выше 8 кГц (int8 режет, float нет).

## §3. Картинки через Yeta (проверено 30.10)

Эндпоинт `POST https://platform.yeta.ai/v1/images/generations`, авторизация
`Bearer YETA_API_KEY`. Работает — вернул живой JPEG.

```json
{"model":"seedream-5.0-flash","prompt":"рыжий кот","n":1,"size":"1024x1024"}
```

Ответ: `{"data":[{"url":"https://...jpeg","size":"1024x1024","output_format":"jpeg"}],
"usage":{"generated_images":1}}`.

**Ограничения, проверенные вживую:**
- `size` минимум ~921 600 пикселей (1024×1024 подходит, 512×512 — отказ
  `image area must be at least 921600 pixels`).
- Модели картинок НЕ работают через `/chat/completions`: `seedream-4.5` отвечает
  `does not support this api`. Только `/images/generations`.
- Есть RPM-лимит: `seedream-5.0-flash` может ответить `TooManyRequests` — нужен
  повтор с паузой.
- Ссылка на JPEG живёт 24 часа (`X-Tos-Expires=86400`) — скачивать сразу.

**Доступные модели картинок:** `seedream-5.0-pro`, `seedream-5.0-flash`,
`seedream-5.0-lite`, `seedream-4.5`, `seedream-4.0`, `seededit-3.0` (правка фото).
Видео у Yeta нет — только картинки.

**Что сделать:**
1. Инструмент `generate_image(prompt, size)` — модель сама зовёт его, когда
   просят картинку. Скачивает JPEG в `cache/generated/`, возвращает путь.
2. Показ картинки в ленте чата (сейчас вложения только входящие).
3. Кнопка «Сохранить в галерею» на сгенерированной картинке.
4. Отдельный ключ Yeta в настройках (тот же `LocalProviderPrefsStore`, другой алиас).

## §4. Память с сервера — перенести владельца

На сервере в `/root/.hermes/memories/` два файла: `MEMORY.md` (8038 байт, о
машине и окружении) и `USER.md` (8302 байта, о владельце). Задача — перенести
то, что относится к человеку, машине и мопеду, в память телефона.

**Не переносить:** серверные пути (`/root/...`), имена хостов и IP, детали
systemd-юнитов, VPN, FCM — на телефоне это мусор, занимающий лимит 8000 знаков.

**Переносить:** кто владелец (имя, город, стиль общения), железо (PCLite, POCO F5,
VW Golf 4, мопед VMC Monster Plus), привычки и предпочтения.

Формат: по одной записи на факт, коротко, третье лицо. Лимит 8000 знаков —
уложиться, лишнее отбросить по приоритету (владелец → техника → прочее).
